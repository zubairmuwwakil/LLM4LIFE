## Important bugs already found and fixed

Do not reintroduce these:

### Date parser / recurring evidence

The first real structured-memory run exposed three correctness problems that were fixed in PR #29:

- a memorial/passing line containing unrelated birthday wording was misclassified as the known person's birthday;
- recurring calendar evidence produced duplicate birthday proposals for the same semantic date;
- an explicit anniversary year was dropped.

The parser now prioritizes sensitive death/passing language, holds unresolved memorial context, collapses duplicate supporting evidence, deduplicates again during validation, and preserves explicit textual years.

### Relationship extraction coverage

The general relationship reviewer was too narrow for real profile formatting. PR #31 added a profile relationship enricher for explicit `Family & Friends` style sections, including:

- parent (`mom`, `mother`, `dad`, `father`);
- sibling (`sister`, `brother`);
- child (`daughter`, `son`);
- spouse / partner;
- grandparent;
- aunt / uncle;
- niece / nephew;
- cousin;
- friend;
- coworker / colleague.

Resolution order remains conservative:

1. exact mapped Obsidian wikilink path;
2. exact mapped same-folder wikilink;
3. unique already-approved alias from the private People identity review;
4. otherwise hold the target privately.

Plain/fuzzy names never create durable graph edges automatically.

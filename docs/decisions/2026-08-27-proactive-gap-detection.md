# 2026-08-27 — Proactively detect and build missing systems

**Decision:** AI should proactively identify important recurring or consequential life/work domains that lack a reliable canonical owner, durable record, trigger, follow-up path, or retrieval workflow.

When the need is supported by repeated evidence or meaningful consequence, the AI may design and autonomously implement the **smallest useful workflow** when the setup is low-risk, reversible, uses already-authorized tools, and stays within existing permissions.

**Reason:** Optimizing only existing workflows leaves an important failure mode untouched: responsibilities that have no system at all. These gaps are especially costly when deadlines depend on memory, information is repeatedly hard to retrieve, recurring maintenance has no owner, or important state survives only in transient conversations.

**Implementation principle:** check existing canonical systems first -> choose one owner -> reuse an existing capability -> build the minimum viable workflow -> observe whether it reduces friction -> simplify/remove if it does not.

**Anti-goal:** Do not turn life into an ERP system. Do not create databases or dashboards merely because they are possible. One-off facts and low-consequence domains do not justify infrastructure.

**Standing approval:** Low-risk, reversible missing-system fixes in already-authorized tools are pre-approved under the standing recommendation policy.

**Boundary:** This does not authorize new purchases/subscriptions, new credentials or permissions, financial actions, destructive changes, consequential external commitments, material production changes, or other hard-to-reverse actions.

**Policy:** See `docs/GAP_DETECTION.md` and `system.yaml`.
